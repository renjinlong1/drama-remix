# 去尾帧（片尾定帧识别）技术说明

## 问题

短剧平台在每集最后贴一张 1~2 秒的静止定帧（下集预告 / App 引导 / 黑场卡）。
顺剪按"集与集的接缝"连续取片时，这张卡会被一起带进成片，两集之间出现 1~2 秒的静止画面，观感割裂。

## 识别依据

只依赖画面是否在动，不需要语义模型：

1. 抽每集**最后 6 秒**、**8fps**、**96 宽灰度**帧（rawvideo 管道，不落盘）；
2. 计算相邻帧的平均绝对差 `diff`；
3. **末尾必须是定帧**：最后 0.4 秒内每一帧 `diff < 1.0`；
   - 数字片源的静止画面编码后 diff 接近 0；实拍慢镜头/推镜通常还有 2~15 的呼吸感；
4. 从末尾往前吃连续静止段，**碰到第一帧 ≥1.0 就停**——只取最后一段，
   正片中间的静止镜头不会被连带；
5. 再往前补最多 **0.3 秒**的淡入/渐隐过渡（只认 `diff < 3.0` 的帧），
   但**不把正片动作当入场动画**；
6. 卡片长度 = 集长 − 起点。上限 4 秒，不足 0.45 秒不裁。

> 旧实现固定往前吃 1.2 秒"入场动画"，把定帧前的正常画面一起吞掉：
> 同一部剧真实定帧约 1.5 秒，旧版裁 2.25 秒（多裁 0.75 秒正片），
> 另有 7 集只裁 1.25 秒（少裁 0.3 秒）。

## 参数

| 参数 | 值 | 作用 |
|---|---|---|
| `WINDOW` | 6.0s | 只看每集最后 6 秒 |
| `FPS` | 8 | 0.125 秒时间精度 |
| `WIDTH` | 96 | 灰度帧宽度，够区分"动/不动" |
| `STILL` | 1.0 | 定帧判定的帧差阈值 |
| `FADE` / `FADE_MAX` | 3.0 / 0.3s | 卡片淡入过渡的容差 |
| `TAIL_GUARD` | 0.4s | 末尾至少要有这么长的定帧 |
| `MIN_CARD` | 0.45s | 短于这个不裁（避免误伤正常静止镜头） |
| `MAX_CARD` | 4.0s | 上限（超过多半是长黑场，按 4 秒处理并降置信度） |

## 边界情况

| 情况 | 处理 |
|---|---|
| 定帧不足 1 秒（如 0.6s） | 照常裁，置信度降为 `mid`；实测 0.6s 素材识别 0.64s |
| 多段定帧 | 只取**最后一段**：从末尾往前遇到第一个"在动"的帧就停，中间静止镜头不动；合成用例 "运动-静止-运动" 识别为 0 |
| 超长定帧（5s） | 按 4s 上限裁，置信度 `low`，前端明细标「超上限」 |
| 识别不到 | **不裁**（旧版会盲猜 0.8 秒，可能切进正片）；可手动切「固定秒数」 |
| 末尾有台词 | 只保护「跨进定帧起点」的台词；完全落在定帧段内的"台词"多半是卡片文字被 OCR 认出来（实测片尾卡上的 `TR` 曾把裁剪量压成 0），不保护 |
| 过短视频（≤3s） | 不处理 |
| 成片最后一段 / 引导尾帧 | 不裁（只作用于集与集的接缝） |

## 误判风险

- **正片末尾的定格镜头**：如果画面真的完全静止（diff < 1.0）且持续 >0.45 秒，会被当成卡片。
  实拍素材通常有轻微呼吸/噪点（diff 2~15），风险较低；数字片源的纯静止画面风险较高。
  兜底手段：切「固定秒数」或「不去」。
- **卡片带缓慢动画**（缩放/流光）：末尾 diff 可能 >1.0，识别不到 → 不裁，不会误伤。
- **黑场**：全黑画面 diff 接近 0，会被裁；这通常也是想要的。

## 真实数据验证（40 集项目）

| 指标 | 旧实现 | 新实现 |
|---|---|---|
| 识别长度 | 1.25s ×7、2.25s ×32、2.5s ×1 | 1.57~1.83s（28 集 1.58s、5 集 1.57s、4 集 1.70s、3 集 1.83s） |
| 置信度 | 无 | 40 集全部 `high` |
| 与逐帧人工核对 | 多裁 0.75s / 少裁 0.3s | 误差 ≤0.16s |

端到端（第 1 集 → 第 2 集，目标 240s）：

- 接缝裁剪：`第 1 集 −1.58s（card）`
- 成片：**200.99s**（未裁为 202.57s）
- 接缝后画面 vs 下一集开头：灰度差 **3.3**（同一画面）
- 接缝后画面 vs 原集末尾卡片：灰度差 **75.5**（完全不同）
  → 证明成片在接缝处直接切到下一集，没有残留定帧。

## 性能

- 单集检测 ~230ms（8fps × 6s，rawvideo）；结果按 `(路径, mtime, 时长, v2)` 缓存在 `data/tailcard.json`。
- 分析完成后后台预热：24 张缩略图 6 路并发（1.5s）+ 逐集尾帧 4 路并发，用户首次建方案时缓存基本就绪。
